# Outcome Product Specification

版本：0.2 · 状态：设计草案 · 更新：2026-10-14

0.2 变更：新增宿主适配器契约（§12）、作业调度与对账（§13）、失败模型与恢复（§14）、可观测性契约（§15）、参考算法（§16）与符合性测试矩阵（§17）；领域切分见 [DDD.md](DDD.md)。

本规范定义 Outcome 的领域模型、系统边界和实现要求，与实现语言和部署技术无关。

## 1. 规范语言与符合性

MUST / MUST NOT 表示符合本规范必须满足的要求；SHOULD 表示推荐；MAY 表示可选。实现 MUST 声明规范版本、支持范围、偏离项及真实集成验证结果。必须明确区分业务事实、模拟数据、估算和未知值。

## 2. 目标与非目标

目标：以已验收任务成果关联全部投入；支持同质量基准衡量生产力与成本；通过观测、独立评测、实验和线上验证持续改进。

非目标：替代宿主业务验收、重建 Agent 执行框架、从 Trace 推断完成、以评分自动认定业务价值、首期统一全企业业务流程。

## 3. 架构与权威来源

|层|职责与事实归属|
|---|---|
|业务宿主|意图、责任、验收约定、授权用户判定的权威来源|
|执行宿主|Attempt、成果版本、运行投入与可选 Trace 的来源|
|事件接入|认证、租户绑定、映射、校验、幂等、乱序处理、回执与对账|
|任务事实层|保存任务投影、来源事件、版本、投入纠错与验收证据|
|观测层|规则、质量信号、责任、调查、复核与复发记录|
|评测层|样本授权、标签独立复核、标准版本、冻结实验、在线抽样|
|价值层|基准版本、同范围对比、覆盖、冻结报告与价值归因|
|操作界面|任务、待办、详情下钻、治理与指标解释|

任务业务状态只有宿主授权事件可以改变。质量模块 MUST NOT 将评分写成业务通过。凭据 MUST 在服务端安全管理；浏览器提供的租户字段不得作为授权来源。

## 4. 核心对象

所有持久对象 MUST 具有稳定 ID、租户、schema_version、创建时间；写入记录真实用户或服务身份。时间使用 UTC，显示按明确时区转换。

|对象|核心字段|不变量|
|---|---|---|
|Task|source/external_id、意图版本、业务范围、标准版本、责任人、生命周期|任务外部键在来源租户内唯一；业务状态与传输状态分离|
|Attempt|task_id、执行版本、run_id、状态、起止时间、成果引用|重试新增尝试；失败投入保留；一个任务可关联多个 Agent|
|ArtifactVersion|内容或授权引用、版本、摘要、证据、缺失项|历史版本不可覆盖；授权撤销后停止读取内容|
|Verdict|来源用户、意图/标准/成果版本、判定、理由、证据、版本|来源用户授权核验；历史判定纠错留链|
|CostEntry|任务/尝试、类别、金额或未知、币种、来源、证据、状态|类别不能重复归集同一账单；估算与结算区分；纠错留历史|
|BaselineVersion|业务范围、质量标准、成果单位、工时、费率、基准成本、样本来源、有效期|发布不可变；未知不能补零；适用范围必须匹配|
|Signal|触发证据、任务、owner、期限、状态、复发引用|处置不修改业务判定；独立关闭约束|
|DatasetVersion|样本快照、用途、标准、授权、标签状态|发布不可变；同任务族不能泄漏到对照与保留测试两侧|
|EvaluatorVersion|类型、rubric、范围、配置、阈值、成员版本|组合无环；自动判定不能自证独立参考|
|Experiment|类型、数据/样本/标准版本、执行版本、预算、逐样本结果|冻结后不可修改输入；公平比较只允许同输入同标准|
|OnlineDecision / Job|幂等键、概率、是否入选、冻结规则、尝试、结果、投入|未入选也留记录；未知概率不得当总体随机样本|
|Insight|问题、证据范围、假设、建议、责任、验证、状态|证据缺失或过期不得显示为已验证结论|
|Report|截点、范围、公式版本、任务/基准快照、覆盖|冻结可重算；后续改基准不改历史|

## 5. 生命周期与事件

Task 展示状态：执行中、待验收、返工中、已闭环、执行失败、已取消。允许来源受控纠错；生命周期不得仅由到达顺序决定。通过判定只有匹配意图、标准与成果版本且满足终态条件时才计为已验收成果。

Signal：待调查 → 调查中 → 待复核 → 已关闭；待复核可退回调查。同一调查提交人 MUST NOT 自行复核关闭。再次触发已关闭问题产生新信号并关联复发。

基准：草稿 → 待审核 → 已发布 → 已废弃。发布版本只追加；新发布版按适用时间生效。审核人与发布职责由角色授权明确，禁止伪造固定审核身份。

事件最小类型：task.created、attempt.recorded、user.verdict、task.status。成本事件作为后续接入扩展。实现 MUST 提供版本化事件结构和错误契约。

事件 envelope MUST 包含 event_id、schema_version、source、external_task_id、aggregate_sequence、occurred_at、身份与任务关联。服务端将 tenant 绑定认证来源；同 event_id 同摘要幂等，同键不同摘要隔离冲突。版本缺口隔离等待补拉，不静默覆盖；重复、拒绝、隔离、成功与重试回执可查询。成功回执 MUST 在持久提交后返回。

重试采用有界退避与最大次数；失败队列可由授权人重放。重放不生成重复任务、成本和判定；服务重启后不得丢失已确认事件或已排队作业。

## 6. 生产力与基准成本

比较单位是“同业务范围、同质量标准的一份已验收成果”。其他单位如每单、每批、每百次服务 MAY 支持，但 MUST 显式记录数量、单位与换算。跨单位、币种或质量标准不能直接合计比较。

基准成本可直接填写每份金额，或计算为人工基准分钟 / 60 × 时薪费率。直接值优先，必须记录来源；基准 SHOULD 使用真实样本、范围、复杂度和有效期，区分自报、实测和估算。

设 C 为已验收、有匹配基准且实际成本完整的可比任务：

- 实际成本 = 模型 + 工具 + 评测 + 人工交办/审核 + 返工补救等不重叠支出。
- 成本节省金额 = ΣC 基准成本 − ΣC 实际总成本。
- 成本节省率 = 成本节省金额 / ΣC 基准成本；基准为零时显示不可计算。
- 已记录成本 = 当前范围所有任务已知金额之和，包括失败和取消投入；它不是完整总成本。

设 H 为已验收、有匹配工时基准且人工投入完整的可比任务：

- 人工工时节省 = ΣH 基准人工工时 − ΣH 实际人工工时。
- 工时节省率 = 节省工时 / 基准工时。
- 人工效率提升 = 基准工时 / 实际人工工时 − 1；实际为零时不显示无穷倍。

人工效率提升不代表 Agent 延迟或团队产能已实际提升。交付周期可单独定义为交办到最终有效验收的时间，包含等待和返工，不能以模型响应时间替代。

每项指标 MUST 展示单位、有效样本数、已验收总量、缺失原因、基准及公式版本、截点。负节省保留；未验收不计成果，但投入 MUST 纳入经营总成本。可比任务收益与整个部署收益分别报告，不能把失败、接入、平台及治理成本从总体收益中遗漏；总体净收益只有基准范围与全部成本齐全时可计算，否则列明未覆盖投入。禁止用可比子集节省外推所有任务收益。

## 7. 观测、评测与洞察闭环

观测 MUST 展示信号来源、触发规则版本、任务、证据、责任、期限、处置历史和复发。无 Trace 仍能完成核心闭环。

评测输出状态包括 scored、out_of_scope、insufficient_evidence、error；后三者不当零分。标签提交人与独立复核人不同；分歧由第三方仲裁。样本授权、去重及独立标签满足发布条件后才能形成评测版本。

实验分方案对照和判定校准。相同输入与标准才允许逐样本提升与排名；不兼容实验 MAY 描述性并列，但 MUST 标明差异，不生成公平对照结论。校准报告误放行、误拒绝、分母和区间；小样本不宣称稳定提升。

在线规则冻结目标版本、概率、评估器、预算、期限和重试策略。随机抽样与风险抽样分别解释；风险样本均值不能代表总体。完成结果可回流待标注草稿，不能自动成为真值。

洞察分三类：确定事实（成本缺失、回传异常）；待验证假设（某版本关联返工增加）；已验证改进（同标准实验和线上复测支持）。Insight MUST 保留证据引用、样本范围、缺失、替代解释、验证方案与负责人。观察相关性不得写为因果；自然语言摘要 MAY 使用模型，但不得补造数字。

Insight 生命周期：候选 → 证据核验 → 待验证 → 验证中 → 已验证 / 未支持 / 已失效。标准或来源变更后重新评估适用性。任何自动建议影响生产配置都必须经过相应权限与变更流程。

## 8. RBAC 与数据范围

用户 → 租户内角色 → 资源动作权限；租户、团队、业务范围是独立的数据约束。服务端 MUST 在每次读写、导出、后台作业和内容引用处校验权限。管理员不自动拥有宿主业务验收权。

最低动作：task.read/export、cost.write、rule.write、signal.write、quality.offline.write、quality.review.assign/submit、quality.online.write、integration.write、asset.write、baseline.write、identity.write、governance.write。

实现 MUST 使用真实会话，支持撤销生效、服务身份隔离、导出授权、审计和最后管理员保护。敏感数据按最少必要读取，结构化字段白名单脱敏；仅隐藏 UI 不构成数据保护。

## 9. 前端行为

任务、成果、实验、复核、作业、信号、集成及报告详情 SHOULD 为地址可恢复的下钻页面，保持筛选与返回上下文。短编辑表单与确认 MAY 用弹窗，必须支持焦点管理、错误定位和未保存提示。

每页 MUST 区分加载、无数据、筛选无结果、无权限、失败、过期数据。集成 MUST 说明接入对象、责任边界、配置步骤和真实连通状态；本地校验不能显示为网络连通成功。指标不以“无分母”等技术词替代缺失解释。

## 10. 可靠性与可移植性

核心实现 SHOULD 从模块化单体和一个适配器开始，不先建设分布式调度。生产 MUST 支持持久事件/队列、乐观并发、审计、备份恢复与数据导出。外部依赖失败应可隔离，不使已接受任务事实丢失。

核心事实模型与实现语言解耦，适配器只承担认证来源映射与传输，不能重写业务指标。客户数据默认租户隔离，不跨客户训练或共享样本；行业模板共享必须有授权、匿名化和知识产权确认。

规模、可用性、恢复目标、保留期限和数据驻留要求由试点测量与企业约束确定，作为部署 profile 明确，不在本草案中伪称已满足。

## 11. 符合性检查

实现 MUST 声明支持的规范版本，并通过以下核心检查。真实集成未执行时标记为未验证，不得以模拟结果替代。

下列条目编号即 §17 测试矩阵的 TC-ID。

1. TC-01 同事件重复提交只产生一次事实；同键不同内容隔离，乱序缺口可补齐，不能错误闭环。
2. TC-02 用户在宿主通过但回传失败，业务判定与传输状态分别显示；恢复不伪造新判定。
3. TC-03 一个任务多 Agent、多次失败和返工，全部投入保留，最终验收只计一份成果。
4. TC-04 成本未知不补零；账单重复不能重复计费；补录和纠错可追溯。
5. TC-05 基准 200、完整实际成本 130 时节省 70、节省率 35%；实际 230 时为 -30、-15%；基准零不计算率。
6. TC-06 基准工时 2 小时、实际人工 1 小时，节省 1 小时、工时节省率 50%、人工效率提升 100%；实际零时不展示无穷倍。
7. TC-07 成本不完整或未验收任务不进入可比成果收益；所有已知失败投入仍进入经营总成本。
8. TC-08 新发布基准影响当前适用分析，已冻结报告不变；币种、单位或质量不匹配不能直接比较。
9. TC-09 同数据/样本/标准实验可逐样本比较；不兼容实验仅描述性并列，不生成提升排名。
10. TC-10 标注者不能自复核；复核人与提交人不一致；分歧第三方仲裁；草稿变化使旧标签证据失效。
11. TC-11 在线抽样记录未入选决策、入选概率和失败投入；回流样本保持待标注；质量评分不改变业务状态。
12. TC-12 调查提交者不能自行关闭信号；关闭后复发创建关联的新记录。
13. TC-13 越租户、越团队、撤销角色权限、越权导出及后台服务访问均被服务端拒绝；最后管理员保护有效。
14. TC-14 详情深链接刷新、返回筛选、键盘操作、空态、错误、未保存提示在目标浏览器通过。
15. TC-15 接入凭据失效、限流、超时和断网可诊断；重试和重放有审计；“已连接”依据真实检测。
16. TC-16 队列运行中重启可恢复，不丢失确认事件，不重复产生业务副作用；备份恢复在隔离环境演练。
17. TC-17 洞察能回溯证据、覆盖和版本；证据不足标假设；未经线上复测不得宣称真实改进。
18. TC-18 部署收益包含失败、平台、接入和治理投入；可比子集报告不能伪称全量净收益。

## 12. 宿主与执行适配器契约

适配器边界刻意保持最小：一个可移植的读/收内核，加可选的提供方特有能力。不得为"让提供方看起来一致"而抽象掉有用的宿主语义。

### 12.1 必备操作

1. `ingest(event)` — 接收宿主事件信封（§5），返回回执。空事件不发外部请求；认证、租户绑定、幂等、乱序与冲突隔离在此完成。
2. `fetch_tasks_by_states(states)` — 返回配置 scope 内指定业务状态的归一化任务快照，用于启动清理与周期对账。空状态列表 MUST 返回空结果且不发请求。调用方 MUST 把分页或传输失败视为整体失败，不得当作"无任务"。
3. `fetch_tasks_by_ids(ids)` — 返回指定任务的当前完整归一化快照（含标签、责任人、路由资格），用于运行中作业对账与陈旧分派复核。scope 内不可见的 ID 视为"不再可见"，不得合成状态；请求中任一记录畸形时 MUST 失败而非静默省略。

可选回写（如在宿主追加备注、回填报告链接）由适配器 profile 声明；核心调度 MUST NOT 依赖回写成功。

### 12.2 归一化规则

- 必填字段：external_key、business_scope、intent_version、state；缺失即畸形记录。
- 状态比较前 trim + lowercase；宿主原名保留用于展示。
- 责任人、标签、优先级为尽力字段，可归一化为 null 或空列表，不因此判畸形。
- 调度资格（是否可继续处置）由适配器按宿主特有规则派生，核心调度只消费结果并叠加自身标签、认领、重试与并发规则。

### 12.3 错误分类

适配器错误 MUST 可归类为稳定 category 并附可读 message：`auth_failed`、`scope_denied`、`rate_limited`、`timeout`、`transport`、`malformed_payload`、`conflict`。核心逻辑只区分成功/失败与分类，不解析提供方细节。

### 12.4 凭据隔离

凭据 MUST 只存在于服务端；浏览器提交的租户/身份字段不得作为授权来源。评估执行器、Agent 子进程及任何下游执行环境 MUST NOT 继承宿主、账单与身份适配器的凭据环境变量；适配器 profile MUST 声明需从子进程环境剔除的变量名。凭据失效、限流与断网必须可诊断，不得显示为"已连接"。

### 12.5 适配器 profile

每个适配器 MUST 随实现文档发布：支持的 scope 选择、必填/可选字段与默认值、密钥与环境变量名、分页与限流行为、外部键映射、归一化与畸形处理、错误分类映射、需剔除的环境变量。核心实现 MUST NOT 解析提供方原始 payload 或按提供方语义分支。

## 13. 作业调度、并发与对账

在线评测与后台作业使用内部认领状态机，与任务业务状态严格分离。调度权威唯一；分派前 MUST 校验认领与并发。

### 13.1 认领状态

`Unclaimed → Claimed → Running →（Succeeded / Failed / TimedOut / CanceledByReconciliation）`；失败进入 `RetryQueued`，到期回到候选。JobAttempt 阶段：Accepted → EligibilityChecked → Running → 终态。业务状态（执行中/待验收/…）不受认领状态影响，认领状态也不写入 Task。

### 13.2 并发与分派

- 可用槽位 = max(全局上限 − 运行数, 0)；可叠加按租户、按规则上限。
- 分派排序：优先级升序 → 创建时间升序 → 外部键字典序（稳定）。
- 分派前检查：候选可路由、未认领、未运行、未在重试队列、槽位可用。任一不满足即跳过。

### 13.3 重试与退避

失败重试延迟 = min(10000 × 2^(attempt−1), max_retry_backoff_ms)，默认上限 300000ms；正常续跑使用 1000ms 固定短延迟。重试前 MUST 刷新该对象当前状态：已终态则清理并释放认领；不再可路由则释放认领不执行；仍可路由但无槽位则以 `no available slots` 重新入队。

### 13.4 幂等与恢复

同 IdempotencyKey 的决策只记录一次；同键不同内容隔离为冲突。每次 tick 先对账再分派。重启后调度内存态可不恢复：通过对账（fetch_by_states/ids）与已持久作业重建；已确认事件、成本与判定 MUST NOT 丢失，重放不产生重复业务副作用。

### 13.5 对账

每 tick 对运行中作业：按最近事件时间与开始时间计算停滞，超过 stall 上限则终止并入重试（上限 ≤ 0 时关闭停滞检测）；刷新宿主状态，终态 → 终止并保留失败投入，活跃 → 更新快照，不再可路由 → 终止不清理。刷新失败时保持运行，下 tick 重试。

## 14. 失败模型与恢复

### 14.1 失败类别

1. 事件/配置：信封非法、schema 不兼容、规则版本缺失、阈值非法。
2. 接入：认证失败、限流、超时、断网、畸形 payload、冲突。
3. 执行：评估器 error、Agent 不可达、预算耗尽、工具失败。
4. 调度：槽位耗尽、认领冲突、重试耗尽、停滞。
5. 可观测性：日志 sink 失败、快照超时。

### 14.2 恢复行为

| 失败 | 行为 |
| --- | --- |
| 事件校验失败 | 拒绝并回执，不半提交；可诊断分类 |
| 接入失败 | 有界退避重试；不丢失已确认事实 |
| 评估器 error | 计 error 状态，不当零分，保留证据 |
| 预算超限 | 进入预算限流，保留已投入 |
| 对账刷新失败 | 保持运行，下 tick 重试 |
| 日志/快照失败 | 不影响核心闭环，不崩溃服务 |
| 重启 | 对账 + 作业重建；已确认事件与成本不丢 |

### 14.3 运维介入点

宿主状态变更（触发取消与对账）、规则禁用/阈值调整（对后续决策生效，不改已冻结决策）、失败队列重放（授权人）、服务重启（进程恢复手段，非常态配置手段）。

## 15. 可观测性契约

结构化日志 MUST 携带：tenant、task_id、event_id、job_id、run_id、attempt、action outcome 与简短失败原因；禁止整包 dump 原始 payload。运行时快照（OPTIONAL）建议返回：

```json
{
  "generated_at": "2026-10-14T12:00:00Z",
  "counts": {"running": 2, "retrying": 1},
  "running": [{"job_id": "j1", "rule": "R1", "task_id": "T1", "attempt": 1, "started_at": "…", "last_event_at": "…", "state": "Running"}],
  "retrying": [{"job_id": "j2", "attempt": 3, "due_at": "…", "error": "no available slots"}],
  "totals": {"evaluated_samples": 40, "recycled_drafts": 6, "budget_spent": 1.2}
```

状态面与日志 MUST NOT 成为正确性依赖；快照失败返回 timeout/unavailable，核心闭环继续。

## 16. 参考算法（语言无关）

### 16.1 事件接收入口

```text
on_event(envelope):
  if !authenticated(envelope): return receipt(rejected, auth_failed)
  key = envelope.event_id; digest = sha256(payload)
  if receipt_exists(key):
    if digest_matches(key, digest): return receipt(duplicate)
    else: return receipt(quarantined_conflict)
  if envelope.schema_version unsupported: return receipt(rejected, incompatible)
  if sequence_gap(envelope): isolate(envelope); await_backfill(); return receipt(gap)
  command = acl.normalize(envelope)          # 防腐层
  with transaction: task.aggregate.apply(command)
  persist_receipt(key, digest, accepted)
  return receipt(accepted)                   # 持久提交后才返回成功
```

### 16.2 轮询-分派 tick

```text
on_tick(state):
  state = reconcile_running_jobs(state)      # 先对账
  if !validate_dispatch_config(): skip_dispatch(); return
  tasks = adapter.fetch_tasks_by_states(active_states)
  if failed: log_and_skip_tick()
  for t in sort_for_dispatch(tasks):
    if no_available_slots(state): break
    if eligible(t, state) and !claimed(t.id): dispatch(t)
```

### 16.3 对账运行中作业

```text
reconcile(state):
  for job in state.running:
    if now - job.last_event_at > stall_timeout: terminate(job, retry=true)
  refreshed = adapter.fetch_tasks_by_ids(running_task_ids)
  if refreshed failed: return state           # 保持运行，下 tick 重试
  for job in state.running:
    snap = refreshed[job.task_id]
    if snap is missing: terminate(job, retry=false)
    elif snap.state in terminal_states: terminate(job, retry=false); archive_failure_investment(job)
    elif snap.routable: update_snapshot(job, snap)
    else: terminate(job, retry=false)
```

```text
schedule_retry(job, attempt, error):

replay(failed_batch, idempotency_key):       # 授权人触发
```
